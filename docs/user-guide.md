# 软件公司管理系统使用说明

这份文档给日常使用系统的员工看，只讲怎么用，不讲技术部署。

## 1. 先记住系统分工

- `经营驾驶舱` 只看全局数据、提醒和风险，不在这里录入业务。
- `财务中心` 负责收支流水、应收应付、附件和财务待办。
- `项目交付` 负责项目进度、任务推进、逾期处理和交付风险。
- `APP 运营` 负责 APP 生命周期、问题记录、资料中心、版本发布和 Bug/升级联动。
- `人员权限` 只给管理员使用，负责员工账号、权限组和操作日志。

## 2. 权限怎么分

系统按“角色组 + 补充权限”的方式分配，和 FastAdmin 的权限组思路一致。

- 先给员工分角色。
- 角色会自带一整组默认权限和默认入口。
- 只有确实存在特殊岗位时，才额外勾选补充权限。
- 普通员工不要直接给管理员权限。

当前角色组建议：

- `系统管理组`：管理员、负责人。
- `财务权限组`：财务、出纳、报销审核。
- `项目交付组`：项目经理、实施、交付。
- `APP 运营组`：运营负责人、产品、增长。
- `客服反馈组`：客服、售后、领导反馈跟进。
- `研发协同组`：技术负责人、测试、研发协同人员。
- `只读查看组`：老板、观察员、只看报表的人。

## 3. 每个岗位从哪里进

### 系统管理组

- 默认入口：`人员权限`
- 先维护员工、角色、权限。
- 再看操作日志和身份切换。

### 财务权限组

- 默认入口：`财务中心`
- 先记流水。
- 再记应收应付和附件。
- 最后处理逾期单据和待办。

### 项目交付组

- 默认入口：`项目交付`
- 先看逾期任务和高风险项目。
- 再更新项目状态、任务状态和截止时间。

### APP 运营组

- 默认入口：`APP 运营`
- 先记问题。
- 再挂研发联动或版本发布。
- 最后补资料、发版结果和客户回告。

### 客服反馈组

- 默认入口：`APP 运营`
- 先记问题记录。
- 有研发需求时再挂 Bug 或升级。
- 回告客户时要写清对象、方式和结果。

### 研发协同组

- 默认入口：`APP 运营`
- 先看研发联动和待发布版本。
- 处理完成后要把结果写回问题单或版本记录。

### 只读查看组

- 默认入口：`经营驾驶舱`
- 只看结果和提醒。
- 需要明细时再跳到对应模块查看。

## 4. 日常使用顺序

### 财务类事情

1. 发生收款、付款、报销、工资等事项，先记 `流水`。
2. 涉及回款或付款节点，再记 `应收应付`。
3. 有凭证就上传附件，没有就后补。

### 项目类事情

1. 先看逾期任务。
2. 再更新项目和任务状态。
3. 风险升高时及时补到系统里。

### APP 运营类事情

1. 先记 `问题记录`。
2. 需要研发处理再挂 `Bug/升级/待发版`。
3. 资料、操作手册、版本说明统一放 `资料中心`。

## 5. 系统内说明怎么用

- 右上角有 `使用说明`。
- 说明会按当前工作身份展示默认入口和操作顺序。
- 如果管理员切换身份，说明也会跟着切换。

## 6. 容易用错的地方

- 不要在 `经营驾驶舱` 找新增按钮，它不是录入页。
- 不要把财务问题记到项目交付里，也不要把项目延期记到财务中心里。
- `人员权限` 不是普通员工的日常工作区。
- 记录当时没有附件，可以先入账，后面再补传。

## 7. 新人培训建议

- 老板和负责人：先讲 `经营驾驶舱`。
- 财务：只讲 `财务中心`。
- 项目组：只讲 `项目交付`。
- 运营、客服、技术：重点讲 `APP 运营`。
- 管理员：最后单独讲 `人员权限`。

不要一上来把所有模块一起讲，否则最容易觉得乱。
